# 08 从零开发功能与面试复习

## 1. 实战任务：开发“用户评价”功能

用下面的流程检验自己是否真正掌握了整套开发方式。

### 第一步：明确需求

- 用户只能评价自己已完成且未评价的订单。
- 一张订单只能评价一次。
- 评分范围 1～5，文字最多 500 字。
- 管理端可以分页查询评价。

### 第二步：设计表

```sql
CREATE TABLE review (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    order_id    BIGINT NOT NULL,
    user_id     BIGINT NOT NULL,
    score       TINYINT NOT NULL,
    content     VARCHAR(500),
    create_time DATETIME NOT NULL,
    UNIQUE KEY uk_review_order_id (order_id),
    KEY idx_review_user_id (user_id),
    KEY idx_review_create_time (create_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

唯一索引既表达业务约束，也能防止并发重复评价。

### 第三步：设计接口

```text
POST /user/reviews                 新增评价
GET  /user/reviews/page            我的评价
GET  /admin/reviews/page           管理端查询
```

### 第四步：定义对象

```java
public class ReviewCreateDTO {
    @NotNull private Long orderId;
    @Min(1) @Max(5) private Integer score;
    @Size(max = 500) private String content;
}
```

再定义 `Review` Entity 和包含订单号、用户名等展示字段的 `ReviewVO`。

### 第五步：Mapper

- 根据 ID 和 userId 查询订单，防止越权。
- 插入 review。
- 使用 JOIN 分页查询展示数据。
- 所有客户端值用 `#{}`。

### 第六步：Service

```text
读取当前 userId
  → 查询订单并确认归属
  → 校验订单状态为已完成
  → 校验是否已经评价
  → 插入评价
  → 更新订单评价标记（如果表中有此字段）
```

若同时写两张表，加 `@Transactional`。即使先查“是否评价”，也必须有唯一索引处理并发竞争。

### 第七步：Controller 与异常

Controller 只做参数绑定、调用 Service、返回 `Result`。越权、状态错误、重复评价转换为明确的业务异常。

### 第八步：测试

至少覆盖：

- 正常评价；
- 评分 0/6；
- 评价别人的订单；
- 未完成订单；
- 重复评价；
- 两个并发请求同时评价；
- 第二张表写失败时事务回滚。

## 2. 开发检查清单

### API

- 路径和 HTTP 方法是否语义清楚？
- DTO 是否只暴露允许修改的字段？
- 参数是否做格式和范围校验？
- 分页大小是否有限制？
- HTTP 状态码和业务错误码是否合理？

### 数据库

- 字段类型、非空、默认值是否正确？
- 是否需要唯一索引和普通索引？
- 金额是否使用 DECIMAL/BigDecimal？
- SQL 是否可能全表扫描或 N+1？
- 并发约束是否只依赖“先查后写”？

### 业务与事务

- 规则是否在 Service 而不是 Controller？
- 多表写操作是否具有正确事务边界？
- 异常会不会被吞掉导致不回滚？
- 外部消息与数据库事务如何协调？
- 重试或重复请求是否幂等？

### 安全

- 是否验证登录、权限和数据归属？
- 是否存在 SQL 注入、越权、敏感日志？
- 密码是否用安全哈希？
- 第三方回调是否验签、验金额、做幂等？

### 可维护性

- 是否使用构造器注入？
- 是否存在魔法数字、重复代码、过长方法？
- 日志是否包含必要业务标识？
- 是否有自动化测试和数据库迁移？

## 4. 一分钟讲清请求链路

> 客户端请求先到 Spring MVC 的 DispatcherServlet，匹配到 Controller 前会经过 JWT 拦截器。拦截器解析 token，将用户 ID 放入 ThreadLocal。Controller 负责参数绑定和统一响应，Service 执行业务校验并管理事务，Mapper 代理将方法映射为 SQL，通过连接池访问 MySQL。查询结果映射为 Entity 或 VO，再由 Jackson 序列化成 JSON。热点查询会先访问 Redis，业务异常由全局异常处理器统一转换。

## 5. 高频面试题速答

### Spring / Spring Boot

**IOC 是什么？** 对象的创建和依赖关系由容器管理，降低耦合并方便替换与测试。

**AOP 是什么？** 通过代理把事务、日志、审计等横切逻辑织入目标方法，避免散落重复代码。

**Bean 生命周期大致怎样？** 实例化、属性注入、Aware 回调、前置处理、初始化、后置处理，容器关闭时销毁。

**Spring Boot 的价值？** starter 管理依赖，自动配置减少样板配置，内嵌服务器和外部化配置简化交付。

### Spring MVC

**请求如何找到 Controller？** DispatcherServlet 接收请求，HandlerMapping 查找 Handler，适配器执行 Controller，消息转换器处理请求体和响应体。

**`@RequestBody` 与普通对象参数区别？** 前者从 HTTP Body 反序列化 JSON；普通对象通常从查询参数或表单字段绑定。

### MySQL

**索引为什么加快查询？** B+Tree 降低查找和磁盘访问范围，但需要额外空间和写维护成本。

**事务四特性？** 原子性、一致性、隔离性、持久性。

**怎样优化慢 SQL？** 定位慢 SQL，用 EXPLAIN 分析扫描与索引，减少返回列/行、修正索引和 SQL，再压测验证。

### MyBatis

**`#{}` 与 `${}`？** `#{}` 使用预编译参数，安全且有类型处理；`${}` 直接拼接，必须白名单控制。

**动态 SQL 有哪些标签？** `if`、`where`、`set`、`foreach`、`choose/when/otherwise`。

**Mapper 为什么没有实现类？** MyBatis 使用 JDK 动态代理生成实现，根据方法定位 mapped statement 并执行。

### 事务

**`@Transactional` 原理？** Spring AOP 代理在方法前后开启、提交或回滚事务。

**为什么会失效？** 自调用绕过代理、非 Spring Bean、非可代理方法、异常被吞、异常类型不触发回滚等。

### Redis

**缓存穿透、击穿、雪崩？** 分别是不存在数据反复查库、热点 key 失效并发查库、大量 key 同时失效或 Redis 故障。

**如何保持一致性？** 常见是先更新数据库再删除缓存，并根据一致性要求增加重试、消息或延迟处理。

### 安全与并发

**JWT 与 Session？** Session 状态主要保存在服务端；JWT 携带已签名声明，服务端可无状态校验，但撤销更复杂。

**如何保证幂等？** 业务唯一键、唯一索引、状态条件更新、幂等表或分布式锁。

**如何避免超卖？** 使用带库存条件的原子 UPDATE、乐观锁或合适的悲观锁，并检查影响行数。
