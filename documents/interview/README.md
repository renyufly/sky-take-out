# 项目包装、架构扩展与面试手册

本目录用于把当前“苍穹外卖”教学项目改造成一个更有辨识度、可验证、能继续扩展的面试项目。

## 推荐主场景

建议改造成：**限量活动与场馆预约履约平台**。

它可以服务展览、体育场馆、企业培训、校园活动等场景，核心问题不再是普通 CRUD，而是：

- 限量场次的高并发预约；
- 库存防超卖与重复预约；
- 预约成功后的异步通知、超时释放和履约核销；
- Redis 热点治理、Kafka 事件驱动；
- Docker/Kubernetes 部署、弹性扩缩容；
- P95/P99 延迟、吞吐量、错误率和资源使用率。

现有代码可以低成本映射：

| 当前外卖概念 | 新业务概念 |
| --- | --- |
| 菜品分类 `category` | 活动/场馆分类 |
| 菜品 `dish` | 活动、场馆或课程 |
| 菜品口味 `dish_flavor` | 场次规格、区域、票种 |
| 套餐 `setmeal` | 联票、系列课程、组合权益 |
| 购物车 `shopping_cart` | 待预约清单 |
| 订单 `orders` | 预约单/购票单 |
| 订单明细 `order_detail` | 场次与权益快照 |
| 地址簿 `address_book` | 联系人/参与人信息 |
| 店铺状态 | 平台或场馆开放状态 |
| 接单、派送、完成 | 确认、待核销、已履约 |

## 最重要的原则

简历只能写你真正实现并能解释、演示或提供压测报告的内容。

下列说法不能混用：

- **已实现**：代码、配置和测试都存在，可以现场演示。
- **已压测**：有固定硬件、数据量、脚本、时长和报告。
- **设计方案**：完成设计但尚未落地，应写“设计了”或“规划”。
- **目标指标**：这是 SLO 或验收目标，不是实测结果。

不要直接把文档中的示例数字复制到简历。先按第 6 章执行压测，再填入自己的结果。

## 推荐落地顺序

```text
业务改名与状态机
  → MySQL 表与核心预约链路
  → Redis 缓存、幂等、库存 Lua
  → Kafka 异步落单与通知
  → 自动化测试和压测
  → Docker 镜像
  → Kubernetes 部署、监控和 HPA
  → 故障演练与压测复验
```

先解决正确性，再优化性能；先单机可验证，再做分布式扩展。
